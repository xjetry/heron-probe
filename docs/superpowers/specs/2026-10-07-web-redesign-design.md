# Web 前端改版：设计

本文定公开页与管理面板的视觉系统、页面结构与数据边界，是后续在 `web/` 落地的依据。§ 引用指[架构设计](2026-09-17-probe-architecture-design.md)。高保真稿在 Stitch 项目 `heron-v3`（`projects/16775736117433058137`），生成它们的规范与提示词在 `docs/design/stitch/`。

## 1. 目标与非目标

改版解决四件事，按生产面板（153 个节点、46 在线）的实际截图归因：

| 问题 | 证据 | 对策 |
|---|---|---|
| 信息看不清 | 公开总览 153 张等高卡片，整页 17,500px，离线卡全是「–」却与在线卡同等大小；节点页首屏是低频的流量校正表单，看不到节点当前状态 | 公开总览默认为卡片视图，只给在线与维护中节点出卡片，离线与从未上报列成网格下方的紧凑表；另有按地区分组的状态墙 + 详情侧栏；节点页首屏是实时状态头 |
| 不知道该处理什么 | 管理总览四张指标卡（节点数、平均 CPU、↓、↑）没有一张指向待办 | 总览首行改为「需要处理」：离线、30 天内到期、agent 版本落后、触发中告警 |
| 操作别扭 | 探测任务与告警规则把新建表单铺在页首，节点分配是 153 个复选框；节点表每行堆 7 个控件 | 新建与编辑进右侧抽屉；节点分配改为可搜索多选 + 标签快选；行操作收进 ⋯ |
| 视觉不统一、移动端差 | 公开页仍是旧顶栏，管理端已有侧栏；uPlot 默认网格与方块图例；手机上表格横向溢出 | 一套设计系统两端共用；图表统一样式；移动端表格降级为列表或卡片 |

非目标：不新增接口、不改协议口径；不做主题沙箱（§10.1）内部的主题样式；不做多管理员。所有页面只展示现有 `PublicService` / `AdminService` 已返回的字段。

## 2. 设计系统

单一来源是 `docs/design/stitch/DESIGN.md`（frontmatter 是 token，正文是规则），本节是其摘要。

**颜色。** 主色「鹭蓝」深色 `#5B9BF8` / 浅色 `#2563EB`，只用于链接、选中、焦点环、主按钮；站点设置可替换主色（§10），所以任何含义都不能只靠主色表达。状态色固定、与主色无关：在线 `#10B981`、需关注 `#F59E0B`（到期 ≤30 天、agent 版本落后、探测失败）、离线 `#F43F5E`、从未上报 `#6B7280`、维护中 `#A78BFA`。状态一律「色点 + 文字」。进度条按阈值着色：<70% 中性、70–90% 琥珀、>90% 玫红。深色画布 `#0B0D12` / 卡片 `#12151C` / 边框 `#232836`；浅色 `#F6F7F9` / `#FFFFFF` / `#E4E7EC`；两套等价，默认跟随系统，公开页按站点设置的 `data-theme` 压过系统。

品牌图形（`docs/brand.md`）保持青灰色鹭鸟与琥珀眼点，不随主色变化；界面主色取蓝而非青，是因为青色与在线绿在小尺寸状态点上难以区分。

**字体。** 界面文字 Inter + 系统中文字体；JetBrains Mono 只用于数字、单位、时间、IP、版本号，并开 `tabular-nums`。中文标签、节点名、按钮一律不用等宽。管理端正文 13px，公开页 14px。Inter 与 JetBrains Mono 的拉丁字形随产物内嵌、由 hub 同源提供（`web/src/fonts.ts`；不加载远程字体，见 `docs/brand.md`，CSP 只放行同源），中文不内嵌、回退系统中文字体。日期、时刻与文件选择用自绘控件（`DateInput` / `TimeInput` / `DateTimeInput`、`FileInput`），外观不随浏览器界面语言变化；单选下拉用自绘的 `Select`，弹出的列表不用系统菜单：公开页筛选行（分组、着色依据、排序）的触发按钮与地区 / 标签入口同一外观；管理端节点列表的状态筛选、节点编辑抽屉的配额单位与流量口径、批量添加节点的有效期用它的表单字段形态（标题在上、按钮撑满）。节点编辑的标签输入用自绘候选列表（`SuggestInput`）代替原生 datalist。管理端的勾选框与单选框自绘外观（仍是原生 input），数字框不画浏览器的微调箭头；折叠标题（details）两端统一画随展开转向的箭头。管理端其余页面的下拉仍是原生 select。

**密度与形状。** 表头 32px、行 36px（两行内容 52px）、控件 32px；状态墙方块约 128×56px；卡片约 200px 高。圆角控件 4px、卡片 6px，全圆角只给状态点与胶囊。层级靠 1px 边框与表面明度，只有弹层与抽屉带阴影。抽屉固定右侧 480px。

**动态集合。** 标签与地区由数据产生，数量不定，站长随时增删，筛选器不能假设它们放得下一排。管理端节点页与公开页同用筛选入口（`components/Facet.tsx` 一份实现）：筛选行上只有「地区 全部 ▾」这样的入口按钮，点开后在筛选行下方平铺这一项的全部选项，同一时间只展开一项，选项多于 12 个时面板里出现搜索框。其余管理端页面（探测任务、告警规则与维护静默的作用域）的标签选择仍是多选下拉（标签可搜索，已选以可移除胶囊显示，放不下折叠「+N」）。状态墙按数据里的国家或标签动态分组。

**口径说明。** 「级别 5m，每点 300 秒」「峰值是时间桶内样本最大值」「上报覆盖率不是在线率」这类说明收进 ⓘ 悬停层，不常驻成段落；它们不能删（§6.4、§10），只是不占首屏。

## 3. 公开页

### 3.1 总览 `/`

顶栏 48px 只有：logo（站长未提供时为默认鹭鸟）、站点标题、「实时 · 每 2 秒」、GitHub 仓库图标（只有图标、新标签页打开）、明暗切换、「登录」。没有导航、铃铛、手动刷新、页脚。

汇总条：`在线 / 总数` + 按状态比例的分段条（在线、维护中、从未上报、离线）、实时合计 ↓↑、本周期总流量。

筛选行：搜索（名称、标签、公开备注；框内提示「输入 / 搜索」，按 / 或 ⌘K / Ctrl+K 聚焦）、地区与标签两个筛选入口（标签入口在有标签时出现）、「只看在线」、视图切换 状态墙 / 卡片 / 列表（访客的选择按浏览器记在 localStorage，没选过时为卡片）。状态墙视图多一个「分组」（地区 / 标签，有标签时出现，默认地区）和「着色依据」（状态 / CPU / 内存 / 到期），卡片与列表视图多一个排序（默认 / 到期 / CPU / 流量，两个视图共用同一个选择），三者都是自绘单选下拉。

地区 / 标签入口：按钮写「地区 全部」「地区 日本」「标签 已选 2 个」，有选择时描强调色。点开后筛选行下方的面板依次是 单选 / 多选 切换、（标签多选时）满足任一 / 同时满足 切换、（选项多于 12 个时）搜索框、一句说明，下面是「全部」和各选项胶囊（带当前快照里的节点数）。单选为默认：点一个只看它，点另一个换成它，再点当前那一个回到全部。多选逐个勾选，胶囊前出现勾选框；地区之间取并集（一个节点只有一个地区，交集没有意义，所以地区没有匹配方式切换），标签默认同时满足（与管理端一致），可改为满足任一；界面文案不写「与 / 或」。从多选切回单选只留按选项顺序最前的那一个已选项。两个入口的单选 / 多选与标签的匹配方式各自记在 localStorage，选择本身不记。Esc 收起面板并把焦点还给入口；面板在 DOM 里紧跟自己的入口（Tab 从入口直接进面板），视觉上排在筛选行最后、独占一行。

**状态墙。** 左 2/3 按地区或标签分组，组按在线数降序，组头「🇯🇵 日本 · 18 / 41 在线」只写计数，不写百分比。按标签分组时组集合与写法取 hub 下发的标签并集（与标签筛选同源），一个节点出现在它的每个标签组里，无标签的节点归入最后的「无标签」组。方块：名称、状态点、CPU / 内存细条与百分比；离线写「离线 · 3 天前」并变淡，从未上报灰色，维护中紫色且不附原因。右 1/3 固定详情面板随点选切换：名称、国家、状态、公开备注、标签、系统 · 虚拟化 · 架构、CPU 型号与核数、运行时长、CPU / 内存 / 交换 / 磁盘条、负载 1/5/15、网络速率 + 1 小时迷你线、本周期流量、磁盘读写、连接数与进程数、费用、到期，底部「查看完整历史 →」。153 个节点约两屏放完。

**卡片视图（默认视图）。** 5 列，只放在线与维护中节点：名称 + 国家 + 状态徽章；系统 · 虚拟化 · 架构，行尾 IPv4 / IPv6 标记（放标题行会把名称挤到截断）；CPU / 内存 / 磁盘三条；网络速率 ↓↑ 现值（卡片没有迷你线：公开请求按来源限流，桶 60、每秒补 10，不能为每张卡片各发一次历史查询；迷你线只在详情面板为选中的一个节点查）；卡片最下方依次是本周期、费用、到期（带剩余天数，≤30 天琥珀）、运行时长四行，没有值写「–」。离线与从未上报列在网格下方一个默认展开、可收起的分组里，是紧凑表格（名称、地区、状态、最后上报）；访客收起后，轮询不会把它再展开。

**列表视图。** 与管理端总览同一张实时读数表（`components/ReadingsTable`）：状态点、节点（名称链到节点页，后跟国家徽章与 IPv4 / IPv6 标记）、CPU / 内存 / 磁盘细条与百分比、负载 1/5/15、网络 ↓↑、本周期、运行时长，另加一列到期（≤30 天琥珀），最后是最近上报；缺读数画「–」。全部节点一张表，离线与从未上报不折叠，顺序按排序选择。只用公开快照已有的字段。

### 3.2 节点页 `/nodes/:id`

首屏是实时状态头：名称、国家、IPv4 / IPv6 标记、状态、最近上报、公开备注、标签，右侧六个现值格（CPU、内存、磁盘、↓↑、运行时长、剩余天数）。其下时间窗口 1h / 6h / 24h / 7d / 30d + ⓘ；3 列 10 张图（CPU、内存 / 交换、磁盘、负载、按核负载、连接数、进程数、网络、磁盘速率、steal / iowait）；探测区每任务一张 RTT 图（均值线 + 最小 / 最大带，标题链到对比页）；系统信息卡。公开页不出现 IP、主机名、内核、agent 版本（`PublicFacts` 已 reserved 这些字段，前端不另有来源）。

### 3.3 探测对比 `/probes/:id`

页头：类型徽章 + 目标 + 「N 个节点执行此探测」+ 时间窗口。大图叠所有节点的 RTT 均值线，悬停高亮一条并显示均值 / 最小 / 最大 / 丢包；图下表格（显示开关、节点、均值、最小、最大、丢包率、错误数）可按列排序，丢包率 >1% 琥珀。表下一行写明「丢包率 = 超时数 ÷ 发送数；错误不计入丢包」（`ProbeSample` 的口径）。

### 3.4 手机版

状态墙降级为按当前分组（地区或标签）的单列列表：组头吸顶可折叠，每行状态点 + 名称 + CPU / 内存小字 + ↓ 速率 + ›，点行直接进节点页，不弹侧栏；需关注与维护中做成名称后的小徽章。列表视图每行折成一张卡：首行状态点、名称、最近上报，下面依次是三项用量与网速，负载、本周期、运行时长与到期不显示（与管理端总览的手机布局同一套样式）。地区 / 标签入口点开后，面板同样在筛选行下方展开，胶囊按屏宽折行。节点页图表单列，现值头 2×3。

### 3.5 公开页已关闭

居中 logo + 「公开页已关闭」+ 一句说明 + 「管理员登录」。分享出去的链接要能看出是站点关了而不是链接失效（§10）。这页由 hub 的静态服务直接返回（`internal/hub/web` 的 `closedPage`，自包含、内联 SVG 与样式），不经前端包：关闭时 `assets/` 也是 404。

## 4. 管理面板

### 4.1 外壳

侧栏 232px，导航三组十四项（监控：总览、节点、批量添加节点、探测任务；告警：告警规则、告警事件、维护静默、通知渠道；系统：外观、主题、存储、在线更新、安全、API token）。「批量添加节点」是注册窗口的页面，放在监控组、紧跟节点：它的用途是一次接入多台服务器，页头与说明卡写明窗口限时限量、每台执行一次安装命令、名称默认取主机名，并指向「节点」页的逐台添加，窄屏收为抽屉。顶栏 48px：面包屑、节点快速搜索（入口写「输入 / 搜索节点」，/ 与 ⌘K / Ctrl+K 打开；/ 在输入框里照常输入）、「公开页 ↗」、GitHub 仓库图标、明暗切换、登出。列表页统一为 页头（标题 + 主按钮）→ 筛选行 → 表格；新建与编辑一律在右侧抽屉；行操作收进 ⋯。

### 4.2 总览

首行「需要处理」四张可点卡：离线（附从未上报数）、30 天内到期、agent 版本低于 hub 绑定版本、触发中的告警；每张卡点进去是对应筛选结果。四个数都能从现有响应算出（`Node.last_seen_at`、`Billing.days_left`、`Facts.agent_version` 对 `boundAgentVersion`、`AlertEvent.transition`）。其下实时节点表：状态点、名称、CPU / 内存 / 磁盘（细条 + 数字）、负载、↓↑、本周期、最近上报。

### 4.3 节点

表格行 52px：复选框、序号 + 拖拽手柄、名称（国旗、标签、「公开」、agent 落后徽章）、IPv4 / IPv6（各带探测状态：正常 / 探测失败 / 不支持 / 等待上报）、状态、运行时长、本周期、费用、到期、⋯（编辑、查看详情、移动到…、换 token、删除）。勾选后出现批量条（批量编辑标签、移动到…）。

筛选行：搜索、地区与标签两个筛选入口、状态、30 天内到期、agent 版本落后、清除筛选。两个入口与公开页 §3.1 逐项相同（入口写法、单选 / 多选、标签的满足任一 / 同时满足、搜索框、Esc、面板独占一行），只多一处：标签面板在「全部」之后有一个「无标签」胶囊（带计数），与选标签互斥——选它清掉已选标签，选任一标签或「全部」即取消它，选中时入口写「标签 无标签」。标签入口在有标签、已选无标签或节点上带标签时出现（标签清单取不到时「无标签」照常可选）。过滤在浏览器里按全部节点做（节点页本就轮询不带条件的 `ListNodes`），胶囊计数也按全部节点算；地区之间取并集，标签默认同时满足、可切满足任一，各筛选彼此取交集。URL 里不认识的值当没写，节点里已没有的地区与标签清单里已没有的标签仍列成可取消的胶囊。

搜索（`q`）、地区（`region`，可重复，未知地区写空值）、标签（`tag`，可重复）、无标签（`untagged=1`）、匹配方式（`match=any`，缺省的同时满足不写）、状态、到期、落后都放在 URL 里，从节点详情的「返回节点列表」回来与刷新时原样还原；单选 / 多选是这台浏览器的偏好，记在 localStorage（键与公开页分开，默认单选）。匹配方式单独不收窄列表：它让「清除筛选」出现，但不关闭拖动排序。

编辑抽屉分组：基本（名称、公开、公开备注、私有备注、标签）、地区（查得值只读 + 手动指定）、费用、运行（流量重置日、离线宽限期、维护中）。「添加节点」抽屉填名称后直接给安装命令。

节点详情与公开节点页同结构，状态头多一行 IPv4 · IPv6 · 主机名 · 内核 · agent 版本（落后徽章），右上「编辑」；低频内容进页内 tab：概览 | 流量校正 | Agent 诊断 | 告警事件；上报覆盖率只在 ⓘ 里，并写明不是在线率。

### 4.4 探测任务

列表：类型、目标（单行截断，悬停看全文）、间隔、超时、分配（全部 / 标签：… / N 个指定节点）、⋯（编辑、对比、证书、删除）。新建抽屉：类型分段、目标、间隔、超时；分配方式三张卡片式单选（全部节点 / 动态标签选择器 / 指定节点）；指定节点用「按标签快选」胶囊 + 可搜索多选 + 已选列表与计数。「只保存本次选中的节点，之后标签变化不会改变分配」这句口径保留在抽屉里。

### 4.5 告警

规则列表：名称、类型（离线 / 探测 / 到期 / 资源 / 证书到期）、条件、作用域、通知渠道（这三列在格内折行）、启用开关、⋯；抽屉表单按类型切换条件字段，没有渠道时提示「规则只记录事件」。事件表：时间、节点、规则、变化（触发 / 恢复）、观测值、投递（成功 / 失败重试中 / 静默中未投递）；系统事件（登录、备份）节点列为「—」；顶部按节点 / 规则 / 变化 / 时间筛选，底部「加载更早」。静默与渠道同为表格 + 抽屉，渠道抽屉按 Telegram / Webhook 切字段并带「发送测试」。

### 4.6 系统

在线更新：hub 卡（当前 / 最新 / 绑定的 agent 版本、检查更新）+ agent 表（版本与落后徽章、来源 github / hub、更新状态含进度与失败原因、操作），全选批量更新。agent 表分组排序、组间不画分隔：可更新与正在更新的在前，其次已是目标版本，再次其余（不支持在线更新、尚未报告更新能力），离线与从未上报最后；组内按节点列表顺序，全选与提交也按表格顺序。安全：会话表 + 密码 / TOTP / Passkey 三张卡。API token、批量添加节点、存储、外观、主题套通用的列表 + 抽屉模板。登录页：居中卡片，密码 + 动态验证码（或恢复码）+ Passkey 入口，错误在表单内。

### 4.7 手机版

侧栏变抽屉；「需要处理」2×2；节点表变卡片（状态点 + 名称 + ⋯，三个关键数字，最近上报）。节点页的地区 / 标签面板与公开页 §3.4 同一规则：在筛选行下方展开、胶囊按屏宽折行。

## 5. 图表

uPlot 统一样式：1px 细网格；去掉方块图例；图例无悬停时显示最新值、悬停时显示该时刻值（现状一排「–」是信息看不清的来源之一）；均值实线、峰值同色浅线；折线用直线段；窗口内没有数据时图区中央一行占位说明，不写原因。系列色不与五个状态色混淆。

横轴刻度数由容器宽度决定：相邻刻度至少相隔 80px，所以 1440 宽的三列图约 6 个刻度、390 宽的手机图 3–4 个；刻度文本在手机上去掉日期只留时分（7d / 30d 窗口保留月-日）。这条由共享图表组件统一承载，节点页与对比页都不各自设刻度。

## 6. 数据边界

生成稿与实现都只能用 `proto/heron/v1/public.proto`、`admin.proto`、`query.proto` 已有的字段。公开页禁止：IP 地址（只允许「有没有该族公网出口」的 IPv4 / IPv6 标记）、主机名、内核、agent 版本、任何可用率 / 在线率 / SLA 百分比、离线原因、同步延迟、拓扑、事件日志、告警、页脚、手动刷新、通知铃铛、额外导航。两端都禁止：评价性结论（「状态平稳」「健康」）、数据里没有的规格（KVM、NVMe、线路方向、发包数、采样点数）、没有数据来源的状态徽章。节点状态只有四种：在线、离线（附最后上报）、从未上报、维护中。一个节点只属于一种，维护中优先于其余三种（站长主动摘出的节点，agent 仍在上报也不计入在线）；在线计数、分段条、状态墙、徽章与「只看在线」都用同一个判定（`web/src/lib/status.ts` 的 `nodeStatus`）。

这条边界由 `scripts/stitch/fetch_check.py` 对每张生成稿的可见文本机械核对（禁用词清单 + 顶栏 / 侧栏只允许固定条目），不靠肉眼。

## 7. Stitch 产物与工作流

`docs/design/stitch/`：`DESIGN.md`（设计系统，上传 Stitch 建项目设计系统）、`prompt-preamble.md` 与 `prompt-preamble-admin.md`（每次生成前置的约束，含数据边界）、`prompts/public/*.md`、`prompts/admin/*.md`（逐屏正文）。`scripts/stitch/`：`ds.py`（上传 DESIGN.md 并建设计系统）、`gen.py`（直连 Stitch MCP 端点同步生成一屏）、`fetch_check.py`（下载截图与 HTML 并核对）。

Stitch 的两条约束决定了工作流：MCP 工具调用在生成完成前超时且结果可能丢失，直连 JSON-RPC 约 30 秒同步返回；项目里已有相似页面时，再次生成会被路由成对旧页的修改且不落地。所以每轮改版在新项目里整套重生成，用返回的 screen id 确认是新页。设计系统正文（规则）上传后会丢失，只有 frontmatter 的 token 保留，这就是约束前言必须随每次提示词附带的原因。

## 8. 实施

按页面族分里程碑，每个里程碑可单独合入：共享组件与设计 token（CSS 变量、状态徽章、进度条、迷你线、多选下拉、ⓘ、图表样式）→ 公开页（总览两视图、节点页、对比页、关闭页、手机版）→ 管理外壳与总览（抽屉与 ⋯ 菜单随首个消费者在这里落地）→ 节点列表与抽屉 → 探测与告警（含探测任务列表「分配」列只显示摘要，修掉节点名拼进单元格撑破表格的问题）→ 系统页与登录。验收以 `web/e2e` 从用户入口重跑为准，公开页入口必须断言不出现 §6 的禁止字段。前两个里程碑的计划：`../plans/2026-10-07-web-redesign-public.md`；其余另写。
